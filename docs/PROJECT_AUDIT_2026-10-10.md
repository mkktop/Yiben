## 下一轮应优先处理的技术问题

### 1. PDF 加载生命周期与长会话内存

`src/renderer/src/routes/reader/PdfViewer.tsx` 存在两类风险：

- `fetch().arrayBuffer()` 完成之前卸载，清理函数可能还没有 loadingTask 可销毁；旧异步过程随后仍会新建 pdfjs task。换章节时也未先清空旧 pdf，恢复页码 effect 可能暂时拿旧文档处理新章节。
- PdfPage 的 visible 一旦为 true 就不再回收 canvas；通读长 PDF 后已渲染页持续保留。文件协议虽然在主进程使用流式响应，渲染进程仍读完整 arrayBuffer，尚无 PDF Range 分段读取。

建议每次加载持有独立 AbortController/task，取消后不再新建任务；按章节隔离组件和恢复状态；保留视口附近 canvas，回收远离视口的页面。验证快速切两份 PDF、未加载完退出、长篇滚动后的页码及内存变化。当前 1.60 MB 左右的渲染入口 JS 同时包含 PDF 代码，后续可按路由或 PDF 类型懒加载；这只是构建产物观察，尚未测量启动收益。

### 2. 离线预取与 LRU 的产品语义

`src/main/cloud189/prefetch.ts` 的 done 表示章节下载尝试已结束。下载文件仍受共用 LRU 上限淘汰；当整系列超过容量时，前面已经缓存的章节可能在后续下载时被淘汰。因此“缓存完成”不等于整系列当前可离线阅读。

建议预取结束后核验所有章节/页是否完整，并区分“任务结束”“全部可离线”“部分失败/容量不足”；明确是否提供固定离线内容、固定内容占用和配额策略。清缓存也需与在途下载/预取协调，避免清完又被下载任务重新写入。应覆盖容量小于系列大小、清理中下载、断网重启与失败重试。

### 3. 对核心场景补充可重复验证

当前单测主要覆盖主进程纯逻辑和 store；Electron 自检覆盖本地书库链路，未覆盖阅读器的完整 DOM 交互。下一轮增加 PDF 快速切话、条漫跨话进度/跳页、跨页大图、文件关联冷/热启动、云端 Range 回退、下载取消/限流和缓存容量的回归。性能结论应使用大型真实书库和资源测量。

## 功能缺口与建议顺序

1. **数据库自动备份与恢复**：当前 JSON 仅保存阅读进度/书签，不包含虚拟书架、标签、阅读偏好、元数据编辑等全部用户数据。应使用 SQLite 的一致性备份能力处理 WAL，提供保留数量、恢复前校验和恢复前再次备份；不要直接复制运行中的单个 yudu.db。
2. **离线可用状态与恢复入口**：按系列展示完整性、失败章节、容量不足与重试；与缓存保护策略一起设计。
3. **阅读器可靠性与体验**：先补 PDF 回收与自动化回归，再增加缩略图全览、护眼设置。阅读统计中的 ms 当前恒为 0，尚缺真正的活跃阅读时长。
4. **WebDAV 书库源**：可扩展 NAS/自建云接入，现有 provider 注入扫描管线可复用；实现前定义认证、分页、路径规范化和 Range 回退。
5. **图像增强、在线元数据刮削、元数据回写、系列合并**：源码暂无完整实现，建议作为独立增量。OCR 翻译、多窗口暂缓。

阅读统计、文件关联、虚拟书架/标签、库体检、条漫连续拼接以及 115 接入已经存在，不能继续按早期 backlog 当成未实现功能；已在候选文档顶部补充状态表。
